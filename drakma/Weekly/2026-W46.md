> ## 📚 Learn today
> - **API7 3.10.9 and forwarded headers** – why now: API7's first check asks whether any upstream relies on `X-Forwarded-*` / `Forwarded` → [[API7 Gateway]]
>   - `X-Forwarded-For/Proto/Host/Port` tell an upstream what the *original* client request looked like (client IP, http vs https, host name, port) after it passed through proxies.
>   - Anyone can send these headers. If the gateway passes them on blindly, a client can fake "I came over HTTPS" or "my IP is 10.x".
>   - 3.10.9 only trusts incoming `X-Forwarded-*` from **trusted sources**; from anyone else it overwrites them with what the gateway itself saw (or clears them).
>   - In **production** an **NLB** (layer 4) sits in front of the gateway. An NLB does not add `X-Forwarded-*` headers (only an ALB does), so the gateway's own values are what upstreams will get.
>   - So the risk is an upstream (e.g. a Hitachi service or a redirect URL builder) that reads `X-Forwarded-Proto` or `X-Forwarded-Host` to build links or decide http/https.
>   - How to check: grep the route/plugin config exports for `X-Forwarded` / `Forwarded`, and ask Hitachi whether any service reads them.
>   > [!question]- Quiz (3 questions)
>   > 1. Why is passing a client's `X-Forwarded-Proto` through untouched a security risk?
>   >    **A client can fake this state, which creates a wrong impression by the upstream services depending on it**
>   > 
>   > 2. Does the NLB in front of the production gateway add `X-Forwarded-For`? What does that mean for the upgrade?  **The listening protocol of the NLB matters, TCP can't, TLS can write, overwrite these headers. Hence, if its TLS and it is writing, then it has to be added to the trusted sources**
>   > 3. . Name one kind of upstream behaviour that could break after the upgrade.
>   > [!success]- Answers
>   > 3. The client can fake it (e.g. claim HTTPS or a trusted IP) and fool the upstream.
>   > 4. No – an NLB works at layer 4 and doesn't add HTTP headers, so upstreams get the gateway's own values.
>   > 5. A service that builds redirect/callback URLs or picks http vs https from `X-Forwarded-Proto`/`Host`, or one that allowlists by `X-Forwarded-For`.
